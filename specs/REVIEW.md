# Specification review queue

Everything the agent observes about the specification itself but is not allowed to act on. Written by the agent; cleared by a person.

`specs/` is not the agent’s to change — see **§ The rules** in [`README.md`](README.md). This file is where the findings about the spec files land:

- **Deviations** — a file in this folder departs from a rule the specs set for themselves.
- **Proposals** — the row itself may be wrong, or a better design has presented itself. Needs a human decision.
- **Drafted rows** — paste-ready register lines, written here because the register may not be edited.

**An entry lives where its fix lands.** A finding belongs here when the spec file is the thing that is wrong or missing. It belongs in [`../REVIEW.md`](../.claude/REVIEW.md) when the repository is the thing in question — even where one way out of it is a new row. The two were one file until 2026-09-21.

**This file is the queue, not a specification.** It carries no 🔒 banner, no register and no prefix, and the agent writes it directly — a queue a person has to paste into is a queue that stays empty. `guard-protected-files.mjs` and `check-spec-banner.mjs` both except it by name. The folder-wide prohibition in [`README.md`](README.md) still reads as covering it; the amendment that would say otherwise is proposed below, and is a person’s to apply.

Every entry cites a spec ID. Nothing personal goes in this file.

| **ARC-003** | **Final form, superseding every earlier redraft in this queue. ### Design-column amendments for the person's own repository · **drafted 2026-09-23** · **applied 2026-09-23**

The owner decided on 2026-09-23 that the record lives in a repository on the person's own account, with the person its only member and the developer not a member. Four design columns assume otherwise. Statements and rationales unchanged; only the design column below replaces the current one.

**PRV-001, "Only she can open the record."**

> A private repository on the person's own account, with the person its only member and the developer in no role, plus a login gate on any deployed surface. Sessions are signed, expiring and HttpOnly, naming the account they were issued to. Falls short in that the code host and the model's vendor can still read what passes through them, under their own terms.

**DEP-001, "The record outlives the loss of any one place it is kept."**

> Host a private, single-member repository on the person's own GitHub account, and keep a clone on the person's own computer that pulls on a schedule, so the second copy stays current without the person doing anything; treat every other checkout as scratch, and encrypt that computer's disk. GitHub is the owner's choice, and the safer one: the person's computer alone is more private, but would fail this row the day it was lost. Falls short in two places: the local copy is only as fresh as its last pull, so a session since then is missing until the computer next wakes; and a copy on a laptop can be stolen, which disk encryption covers only while it is off.

**DEP-002, "Reaching it takes nothing but a device she already carries."**

> Reach it through the Claude app on the person's phone, signed in to the person's own Claude account and connected to the person's own GitHub, which opens a session on a cloud machine against the repository — set up once, with help, and never again. **DEP-004, "Any change to how it works reaches her next session without her doing anything."**
