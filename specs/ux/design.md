# Dashboard Design [DES]

The binding design specification for the read surface: how it looks and behaves, its chrome, its typography, and what must stay true of both as the theme and the record change.

> 🔒 **An agent may not edit this file.** The prohibition extends to any alteration of it, rewording, reformatting, renaming and moving included, and admits no exception for a change the agent judges harmless. Where an agent finds anything wrong, inconsistent or improvable, it records the finding in [`REVIEW.md`](../REVIEW.md) with its reasoning and leaves the entry for a person to clear, never treating its own entry as settled. Until a person applies a change, this file is complied with as written; where it and the repository diverge, the repository is wrong.

## Purpose and Scope

The provisions below fix this specification's purpose and the reach of its authority — how this file is to be read, obeyed, and bounded. The register further down governs the surface's appearance and behaviour instead.

| #   | Provision                                                            | What it means                                                                                                                                                                                                                                                                             |
| --- | -------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| 1   | **This specification is the single source of truth for how the surface reads.** | A stylesheet records what a rule currently says and commit history only what changed; neither records what the surface was meant to look like or why. This file records both, and an agent treats it as the source of truth in every change it makes to the surface's appearance. The reading rules, the binding rule and the approval gate in [`README.md`](../README.md) apply to this file unchanged. |
| 2   | **It governs appearance and behaviour, never reach, capability or location.** | What is **not** here: where the surface may read from and what it may send, which is [`privacy.md`](perimeter.md) (`DPV`); what the surface is for and what it refuses to show, which is [`purpose.md`](purpose.md) (`DSH`); and where its files live, which is architectural (**ARC-003**). |
| 3   | **This specification binds where it speaks and defers where it is silent.** | Compliance is mandatory: an agent chooses how to satisfy a row, never whether to. Where this file is silent, the agent decides; silence confers no authority to invent a requirement and attribute it here. Every row states the test by which compliance is judged, and a row without one is a gap to raise. |

## Specifications Register

The normative part of this file. Each row is one thing that must be true of the surface's appearance and behaviour; how a row is read is in [`README.md`](../README.md).

> ⚠️ **When referencing:** always cite a row by **both** its ID and its spec statement — IDs shift, specs get removed, and ordering isn't guaranteed.

| ID | SPEC STATEMENT | SPEC RATIONALE | DESIGN RECOMMENDATION |
|---|---|---|---|
| **DES-001** | Each recurring piece of chrome has one appearance across the whole surface. | A scrollbar, a code span, a section marker: the eye reads each as part of the paper or as part of the window, and two answers on one screen read as unfinished rather than as varied. The cost of letting them diverge is paid quietly — a treatment written for one column, then the browser's default everywhere else, and nobody notices until a screenshot shows both. Compliance is judged by count: one definition per piece of chrome, in one place, with no component restating it. | State it once on the root and let inheritance carry it, where the property inherits. It works because the declaration and the thing it governs cannot drift apart when there is only one of them, and because anything added later is covered without being told. Its reach is limited: properties that do not inherit — a reserved gutter, a sticky offset — still have to be declared per container, so the rule is "one definition per piece", not "one rule per file". |
| **DES-002** | On a screen wide enough for columns, only the reading column moves. | Navigation that travels is navigation that has to be chased back. The index beside a document and the contents list across from it are both answers to "where am I", and an answer that scrolls away leaves the reader scrolling to find out where they were. Without it the first screenful of every document is spent watching two columns drift upward. The test is mechanical: scroll any long view and the two outer columns must not move by a pixel. | Fix the shell to the viewport and let the middle column scroll inside it, rather than making the rails sticky. Sticky nearly does this and not quite — a sticky column still travels until its top reaches the offset, and stops pinning once its containing block has passed. The cost is that the document itself no longer scrolls, so scroll restoration and find-in-page act on the column; both still work. Not applied below the stacking breakpoint, where a nested scroller is a trap, nor when printing, where there is no viewport to fix to. |
| **DES-003** | Nothing the surface renders depends on a glyph the reader's font may not carry. | A character the font lacks is silently drawn by a different font, so one line arrives in two faces with two stroke weights and two sets of vertical metrics. It cannot be styled away and it cannot be noticed in review, because the author's machine has the font that works. The cost is a diagram that reads as broken on every machine but one. The test: a block renders identically with the page's fonts unavailable. | Write diagrams in characters every monospace font carries — letters, digits, punctuation, spaces. It works because the failure is font coverage, not layout, and the only reliable fix is to need less coverage. The alternative is to ship a font subset that includes the range, which is sound and costs a build step and a licence check; either satisfies the statement. Its limit: it cannot help with characters the record itself contains, which are hers and not the surface's to choose. |
| **DES-004** | Every visual value comes from the theme, so no change of hue, character or mode can break the surface. | The theme is three axes the reader controls, and a hardcoded colour is a value that silently stops agreeing with the other two. Worse, a hardcoded contrast is one the build's own gate never sees, so it cannot be caught. The cost is a surface that is correct in the state it was authored in and wrong in eleven others. Compliance is judged by the gate: it sweeps the whole circle and refuses a palette that fails anywhere on it. | Reference tokens, never literals, in every rule that carries a colour, a radius, a duration or a face. It works because the gate and the stylesheet then read the same values, so a failure is a build failure rather than a discovery. Limited to what tokens exist: a rule needing a value the theme does not name should add it to the theme rather than inline it, and a value that genuinely cannot vary — a hairline's one pixel — is not a theme concern. |
| **DES-005** | Anything quoted out of the repository is distinguishable from the prose around it, and from anything the reader can act on. | A path, a filename or a spec ID inside a sentence is a precise thing, and prose that reads it as ordinary words loses the precision. But the surface also has links, and a quoted thing that looks clickable is worse than one that looks like prose. The cost of getting it wrong is a reader who clicks a filename, or who skims past the one exact term in the sentence. The test is a paragraph containing both a code span and a link: each must be identifiable without reading the words. | Give the quoted span a ground and a face of its own, and let a link keep the colour that says it is a link. It works because the two cues are independent — one says "quoted", the other says "goes somewhere" — so a span that is both can carry both. A block gets one ground around the whole of it rather than per line: the inline treatment paints a box per line box, which stripes a listing. |
| **DES-006** | Every section of a document is addressable, and the surface says which one is being read. | A long specification is opened for one rule, not read front to back, and a document that can only be reached as a whole is one the reader scrolls. The marker matters as much as the anchor: a contents list that shows where you can go and never where you are is half a navigation. The cost is measured in scrolling. The test: every heading has a link that reaches it, and the contents list marks a section for the whole time that section is under the eye — including the first and the last. | Derive an anchor from the heading's own text, and mark the active section from measured offsets rather than from an observer's band. Offsets answer everywhere on the page; a band in the middle of the viewport has no answer at the top, where nothing has reached it, or at the bottom, where the last heading never does. Measure once and compare numbers on scroll, so the test costs nothing per frame. Its limit: an anchor derived from a heading changes when the heading is reworded, which breaks any link saved to it. |
