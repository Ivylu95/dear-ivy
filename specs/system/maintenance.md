# Maintenance [MNT]

The binding specification for the unattended maintenance run: when it may fire, what evidence it owes, and what it may never touch.

> 🔒 **An agent may not edit this file.** The prohibition extends to any alteration of it, rewording, reformatting, renaming and moving included, and admits no exception for a change the agent judges harmless. Where an agent finds anything wrong, inconsistent or improvable, it records the finding in [`REVIEW.md`](../REVIEW.md) with its reasoning and leaves the entry for a person to clear, never treating its own entry as settled. Until a person applies a change, this file is complied with as written; where it and the repository diverge, the repository is wrong.

---

## Purpose and Scope

The provisions below fix this specification's purpose and the reach of its authority — how this file is to be read, obeyed, and bounded. The register further down governs the unattended run instead.

| #   | Provision                                                                 | What it means                                                                                                                                                                                                                                                                                                                           |
| --- | ------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| 1   | **This specification is the single source of truth for unattended work.** | A run leaves a log of what it did, and commit history what it changed; neither records what it was permitted to do. This file records both, and an agent treats it as the source of truth every time it acts without her in the room. The reading rules, the binding rule and the approval gate in [`README.md`](../README.md) apply to this file unchanged. |
| 2   | **It governs what the system may do, never the boundary it does it in.**  | The boundary that makes self-editing safe is set elsewhere (**SFG-001**, **DAT-003**); what the system may do inside that boundary lives here. Where a maintenance question turns on whether something may be written at all, architecture settles it. |
| 3   | **This specification is subordinate to safety at every point.**           | **SAF-005** suppresses this file entirely: nothing is filed, tidied or researched during or immediately after a crisis, and the suppression is state on disk rather than something a run remembers. A run that cannot read that state does not run. |
| 4   | **This specification binds where it speaks and defers where it is silent.** | Compliance is mandatory: an agent chooses how to satisfy a row, never whether to. Silence confers no authority to widen the run's reach — an unattended action no row anticipated is a proposal, not a decision, and MNT-002 says where it goes. |

## Specifications Register

The normative part of this file. Each row is one thing that must be true of the unattended run; how a row is read is in [`README.md`](../README.md).

> ⚠️ **When referencing:** always cite a row by **both** its ID and its spec statement — IDs shift, specs get removed, and ordering isn't guaranteed.

| ID | SPEC STATEMENT | SPEC RATIONALE | DESIGN RECOMMENDATION |
| --- | --- | --- | --- |
| **MNT-001** | Maintenance never interrupts, never asks, and never runs at a bad moment.    | "Silently" includes not reporting success. A maintenance run she hears about is a system asking to be managed.                                                                       | Triggered on elapsed sessions or elapsed time; run between sessions rather than within one. Suppressed by the crisis marker from SAF-005.                                                    |
| **MNT-002** | Unsupervised editing cannot lose anything.                                   | The proposal path is what makes autonomy safe. Give the system somewhere to put a judgement it isn't allowed to act on, or it will act on it.                                        | Inherits DAT-003 wholesale. Anything the system believes should truly go is left in place and raised as a proposal rather than acted on.                                                     |
| **MNT-003** | A self-update is traceable to real evidence, one change at a time.           | "Opened, or only its record reached" isn't pedantry. It's the difference between a citation and a plausible-looking string — and only the run itself knows which it did.             | One change per run, each tied to a citation, each committed separately so it reverts alone. Record the evidence tier, and whether the source was actually opened or only its record reached. |
| **MNT-004** | A research run is never primed to confirm its previous answer.               | Ordering is the mechanism, and ordering isn't enforceable by instruction. Either accept this row as procedural, or move the search into a step that structurally cannot see the log. | Search first; open the log only afterwards. The prior conclusion isn't in context at the moment the question is asked.                                                                       |
| **MNT-005** | A change that makes things worse is reverted, and the reversal recorded.     | The reverted list is worth more than the applied one. Without it, the next run re-proposes the same change with the same reasoning and no memory of the outcome.                     | Watch a fixed number of sessions after each change. A regression reverts and writes its reason to a durable _tried and reverted_ list.                                                       |
| **MNT-006** | Evolution may only strengthen the core — never soften, shorten or remove it. | Self-restraint is not a control. Until the file is unwritable, the core is immutable by agreement — which is another way of saying it isn't immutable.                               | Enumerate the core explicitly: safety, the numbers, nothing-is-deleted, the licence limits, and the rule declaring them immutable. Enforce the boundary at the tool level, per SFG-001.      |
| **MNT-007** | A run that cannot do its job changes nothing, and says so.                   | A run that invents a citation is worse than no run at all, because afterwards it's indistinguishable from a good one.                                                                | With no access to evidence, log the fact and amend nothing. No degraded mode, no reasoning from memory.                                                                                      |
| **MNT-008** | The specs stay in step with the system they describe. | A spec that drifts is worse than none: it is obeyed as written while the system does something else. An empty spec file does not stay empty either — it gets written after the fact by whatever was built. The test: every spec file has at least one row or says why it has none, and every register has been reviewed within its schedule. | Stable IDs [[FAIR F1]](https://book.the-turing-way.org/reproducible-research/rdm/rdm-fair/ "Written for published research data in a registry shared between institutions. The principles transfer as an account of what findability costs; their machinery - resolvable identifiers, schema-validated metadata, an external registry - does not, and here each is upheld by discipline instead."), cited in every commit or proposal that changes a design [[ISO-29148 §5.2]](https://www.modernrequirements.com/blogs/iso-29148-explained/ "The standard itself is paywalled; this is an explainer. The characteristics transfer; its baselining and review apparatus does not.") [[INCOSE-GTWR]](https://www.incose.org/docs/default-source/working-groups/requirements-wg/guidetowritingrequirements/incose_rwg_gtwr_v4_summary_sheet.pdf "Its Trace to Source means the origin a requirement inherits from. These tags are corroboration, a different and weaker attribute."); a disagreement between repository and spec goes to the review queue, never into the spec; each register is reviewed on a schedule, not on suspicion; the link and banner checks catch the mechanical half. The limit: nothing checks meaning — a row can be cited correctly and still describe a system that has moved on. |
| **MNT-009** | An audit changes nothing it audits. | An audit that repairs what it finds grades its own work, and the fix it chose is the one it will next find correct. Its findings go to a person, or it is not an audit. The test: the specs, the harness and the record are unchanged after every audit, and every finding is in the review queue. | A scheduled read-only run checks that safeguards are alive and switched on, every cited ID is defined, every spec names what enforces it, and a clean checkout passes the gate; it writes only to the review queue. Restoring a broken safeguard is a separate job with its own narrow permission. Falls short in that every finding waits for a person, so the audit never shortens the queue it fills. |

> 📚 **Most rows above carry no source tag, and that is a value rather than an omission.** These registers govern one person's private record; where no published work genuinely addresses a row it stays bare, and reaching for a large name to decorate one is the failure mode — see **Source tags** in [`README.md`](../README.md). MNT-008 is the exception, tagged because requirements engineering states what traceable IDs are for. The works cited elsewhere in these specs, and the boundary past which each stops applying, are in [`REFERENCES.md`](../REFERENCES.md).
