# Safeguards [SFG]

The binding specification for the harness’s safeguards: what holds the agent to its rules when a rule is in its way.

> 🔒 **An agent may not edit this file.** The prohibition extends to any alteration of it, rewording, reformatting, renaming and moving included, and admits no exception for a change the agent judges harmless. Where an agent finds anything wrong, inconsistent or improvable, it records the finding in [`REVIEW.md`](../REVIEW.md) with its reasoning and leaves the entry for a person to clear, never treating its own entry as settled. Until a person applies a change, this file is complied with as written; where it and the repository diverge, the repository is wrong.

---

## Purpose and Scope

The provisions below fix this specification’s purpose and the reach of its authority — how this file is to be read, obeyed, and bounded. The register further down governs the harness’s safeguards instead.

| #   | Provision | What it means |
| --- | --- | --- |
| 1   | **This specification is the single source of truth for the harness’s safeguards.** | The configuration shows which checks and denials exist, and commit history when each changed; neither states what they are there to hold. This file states it, and an agent treats it as the source of truth whenever it changes a rule, a check or a permission. The reading rules, the binding rule and the approval gate in [`README.md`](../README.md) apply to this file unchanged. |
| 2   | **It governs what holds the agent to its rules, never what the rules say.** | What the agent must do is the business of every other register; this file governs only what stops those rules being bypassed. Where the safeguard files live is architectural, in [`ARCHITECTURE.md`](ARCHITECTURE.md). SFG-001 and SFG-002 were proposed rows of the architecture register until 2026-09-21; the first was redrafted here, the second moved unchanged. |
| 3   | **This specification binds where it speaks and defers where it is silent.** | Compliance is mandatory: an agent chooses how to satisfy a row, never whether to. Silence confers no authority to invent a requirement and attribute it here; where something ought to hold and nothing here provides for it, the omission is a gap and is raised. |

## Specifications Register

The normative part of this file. Each row is one thing that must be true of the harness’s safeguards; how a row is read is in [`README.md`](../README.md).

> ⚠️ **When referencing:** always cite a row by **both** its ID and its spec statement — IDs shift, specs get removed, and ordering isn’t guaranteed.

| ID | SPEC STATEMENT | SPEC RATIONALE | DESIGN RECOMMENDATION |
| --- | --- | --- | --- |
| **SFG-001** | The agent cannot change its own binding rules without a person’s explicit instruction. | A system that can edit the file declaring its limits has a preference, not a floor, and a rule stated inside the file it protects is circular [[REF-MONITOR]](http://www.cs.ucr.edu/~trentj/cse544-s18/docs/refmon.pdf "Written for access control in OS kernels. The tamperproof requirement transfers; the formal-verification half does not."). The risk is not a rogue edit but a helpful one: a session that finds a rule in its way and tidies it. A person’s instruction, recorded where it was given, is what turns an edit into a decision. The test: every change to a binding file traces to a person’s instruction, recorded beside it. | A hook before every edit-tool write, and every shell command naming the path, refuses `specs/` and `.claude/CLAUDE.md` and points to the draft route: `specs/REVIEW.md`, the folder’s one writable file, or `data/state/proposals.md`. A person’s explicit instruction opens one file for one edit, recorded by a hook on the person’s own message, which the agent cannot write, and logged under Authorised edits. It fails open on a crash. The limit: a shell command can reach a path the hook cannot see in it, and a logged instruction shows an edit was asked for, not that it was right. |
| **SFG-002** | A rule enforced by machinery is distinguishable from one enforced by instruction. | A rule in an instruction file is a request to a model; a rule in a permission list is a fact about the system. Read side by side the two are identical, and the rows that most need to hold are the ones most often only requested — safety is a property of the whole system rather than of the replies it produces [[GENAI-SAFEGUARDS]](https://doi.org/10.3390/healthcare14101395 "Argues safety is sociotechnical rather than a feature of the agent. It describes layers of safeguard; it does not say how a specification should record which layer a rule sits in."). Compliance is judged by asking, of any row, which of the two it is and getting an answer without running the system. | State in each design column what enforces the row and what would still get through — the mechanism named, or its absence admitted. It falls short wherever a mechanism is partial: a startup check proves a rule is present, never that it is obeyed. |
| **SFG-003** | A write that would lose part of the record is refused before it lands. | Nothing written is removed; superseded material moves to the archive. A refused deletion costs one move; a landed one is found, if ever, by a session missing what it cannot name. Compliance is judged by every agent deletion or whole-file replacement of a record file being refused, with the archive named. | A hook before every shell command that deletes or empties a path under `data/`, and every edit-tool write replacing a file there whole, refuses it and points to `data/archive/`. Edits within a file pass. It fails open on a crash. Falls short in that an edit can still drop a line it should have kept, and a person’s deletions pass it untouched. |
| **SFG-004** | A write that would put anything personal outside the record is refused before it lands. | Outside the record is the harness, read by every session and written as though anyone might read it; a name there has left the one place built to keep it. Refused, the write goes where it belongs. Compliance is judged by every agent write carrying a name or line from the record to a path outside it being refused, with the record named as its place. | A hook before every edit-tool write outside `data/` compares the new text with the names on file and the record’s own lines, refuses a match, and points to where under `data/` it belongs. It fails open on a crash. Falls short in that it catches only what it can match: a paraphrase, a nickname or a date from her life passes it, and a shell command writing the same text is not seen. |
| **SFG-005** | A write that broke a rule is reported to its author while it can still be fixed. | Some rules can only be judged on the result: whether a pointer in the finished file resolves, whether a cited row exists. Reported as the write lands, the fix is the next edit; found at commit, it is a search through everything changed since. Compliance is judged by a write leaving a broken pointer or a missing row drawing a report before the agent’s next action. | A hook after every write runs the machine checks on that file alone — its pointers, its cited rows, anything personal — and hands failures back to the agent to fix. It checks only files its own session wrote, since two sessions can share one tree. A check that takes more than a second stays at commit instead. Falls short in that it reports and cannot undo, a fix the agent skips still lands, and a rule spanning several files is not seen by a check of one. |
| **SFG-006** | Outside a crisis, a turn does not end with the record’s promises unkept. | A session can end without warning, and whatever a turn still owed ends with it. Held at the turn’s end, the owed work — an event told reaching the timeline, a write being saved — is done while the context that knows of it still exists. In a crisis the order reverses: nothing is filed, and she is never kept waiting for the record. Compliance is judged by no ordinary turn ending with a told event unrecorded or a write unsaved, and no crisis turn held for either. | Hooks at the turn’s end check that each event told is on the timeline and each write under `data/` is committed and pushed, and hold the turn, with the reason, until it is. Each reads a crisis marker on disk first and stands down when it is set; the check that sees the crisis writes it. Each holds a turn once only, so a check that cannot be satisfied never traps her. Falls short in that whether an event was told is the agent’s judgement, not proved, and a crisis nobody recognised leaves no marker to stand down on. |
| **SFG-007** | A rule a machine can check is checked on every change, whoever made it. | The agent’s tools are one way into the repository among several: a shell command writes without them, and a person edits where no session runs. A check wired to one way in guards one door. Every change passes a commit, whoever made it, so every machine check runs there in full. Compliance is judged by making the same bad change through each way in, and seeing each refused at commit. | A git pre-commit hook runs the whole gate — crisis numbers, settings, privacy, links, perimeter — and refuses the commit on any failure, naming it. It also refuses a commit in which a file under `data/` disappears without reappearing under `data/archive/`. Falls short in that an uncommitted change is never checked, a person can skip the gate, and it cannot tell the agent’s change from a person’s, so a rule only the agent is bound by is not enforced here. |
| **SFG-008** | Before an edit to the harness is finished, the agent has read the specs that govern the file it changed. | Most specs need judgement, not a script — whether a page still shows what is unsaved before its history, say — and their only check is an agent reading them. An agent does not open a spec file nobody pointed it at, so these specs break silently: a change that painted history before the save state went unnoticed until the right spec file was opened by chance. Compliance is judged by editing a governed harness file and finding its specs in the agent’s context before its next action, unasked. | A list in the hooks folder maps path patterns outside `data/` to the spec files that govern them — `ux/app/(dashboard)/changes/**` and `ux/lib/git.js` to `specs/ux/tabs/changes.md`, for instance. After each write, a hook matches the path and hands the agent the statement of each spec in that file, one line each, with the file to open for the rest — about a hundred tokens — and only the first time that spec file comes up in the session. It does this only for files its own session wrote. Falls short in that the list drifts as files move, a person editing directly gets nothing, and an agent handed the right specs can still misjudge them. |
| **SFG-009** | A safeguard that has stopped working is noticed and restored to what the specs require, without anyone looking. | A check that crashes has to let the work through, or one broken check stops every session — so a dead check looks exactly like one that found nothing. The switch that turns checks on fails the same way: one malformed line drops every check and permission with only a passing notice. Noticed but unfixed, it stays dead until a person gets round to it; restored to what the specs require, the fix is a return, not a decision. The test: a safeguard broken on purpose is working again, and reported, before a session relies on it. | A scheduled run between sessions feeds each safeguard a case it must refuse, and reads the live settings rather than the code to confirm each is switched on. A failing safeguard is restored to its last committed version that passed and rewired as the specs require; the restore is re-tested, committed on its own and reported in the review queue. What it cannot restore — no passing version, or specs that do not say — it reports and leaves. The limit: it proves a safeguard fires on the cases it was given, never on the ones nobody thought of, and a restore can bring back a version that passed its tests and was still wrong. |

> 📚 **Both rows carry a source tag: SFG-001 because the reference monitor is where the field first stated that a guard must be tamperproof against the thing it guards, SFG-002 because safety is argued there to be a property of the whole system, not of the replies.** These registers govern one person’s private record; where no published work genuinely addresses a row it stays bare — see **Source tags** in [`README.md`](../README.md). The works cited in these specs, and the boundary past which each stops applying, are in [`REFERENCES.md`](../REFERENCES.md).
