# Architecture [ARC]

The binding architectural specification for this repository: the folder layout, what each folder and file is responsible for, and what must remain true of that structure as the system changes.

> 🔒 **An agent may not edit this file.** The prohibition extends to any alteration of it, rewording, reformatting, renaming and moving included, and admits no exception for a change the agent judges harmless. Where an agent finds anything wrong, inconsistent or improvable, it records the finding in [`REVIEW.md`](../REVIEW.md) with its reasoning and leaves the entry for a person to clear, never treating its own entry as settled. Until a person applies a change, this file is complied with as written; where it and the repository diverge, the repository is wrong.

## Repository Layout

The territory this specification governs: folders first, then files, alphabetical within each, the way an editor lists them.

Every folder has one responsibility; a file whose home isn't obvious here doesn't have a home yet. The accompanying comments are one-line orientation — what must hold of each folder is the Specifications Register below.

```bash
dear-[user]/
├── .claude/                        # agent harness
│   ├── commands/                   # operator-invoked procedures
│   ├── hooks/                      # harness enforcement
│   ├── memory/                     # harness lessons the code cannot show
│   ├── prompts/                    # prompt text for unattended runs
│   ├── skills/                     # one file per session type
│   ├── CLAUDE.md                   # always-loaded instructions
│   ├── REVIEW.md                   # raised, never acted on
│   ├── heartbeats.json             # when unattended runs fire
│   └── settings.json               # permissions and hooks
├── data/                           # everything personal, nowhere else
│   ├── archive/                    # superseded, never deleted
│   └── assets/                     # personal assets, always private
├── knowledge/                      # the evidence base, non-personal
├── samples/                        # invented record, for the read surface
├── specs/                          # what must hold, binding
├── temp/                           # scratch, untracked
├── ux/                             # human read surface
├── .gitignore                      # exclusions, reasoning inline
└── README.md                       # human orientation
```

> 🧭 **The layout above is the owner's design** — what the repository should be, not a snapshot of what is on disk. Build to it.

**Naming.** One form per kind of file, so a listing tells each file’s kind before it is opened — the scheme **ARC-012** asks to be written down here.

| Kind | Form | Example |
| --- | --- | --- |
| Governs or indexes its folder | UPPERCASE | `README.md`, `INDEX.md` |
| Dated entry | `YYYY-MM-DD.md` | `2026-09-21.md` |
| A person | first name | `firstname.md` |
| Other record files | snake_case | `about_me.md` |
| Other harness files | kebab-case | `check-work.md` |
| Code | the language’s own | `ReviewEntry.jsx`, `spec-edit.mjs` |

## Specifications Register

The normative part of this file. Each row is one thing that must be true of this repository; how a row is read is in [`README.md`](../README.md).

> ⚠️ **When referencing:** always cite a row by **both** its ID and its spec statement — IDs shift, specs get removed, and ordering isn't guaranteed.

| ID          | SPEC STATEMENT                                                              | SPEC RATIONALE                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  | DESIGN RECOMMENDATION                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| ----------- | --------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **ARC-001** | Agents keep this repository; people are who it is kept for.                 | Everything here is authored by an agent — the instructions, the tooling, the interface, and the record itself. A person asks and reads; they do not write. So the repository is produced by a reader that cannot ask a question, and kept by one that arrives each session with no memory of the last: anything that must hold has to be in the artefact, because an unwritten rule is not a weak rule to it but an absent one. And it is kept for someone who will never maintain it, which pulls the other way — what is written for a machine to act on is not what a person can pick up. The structure has to answer both. The test: nothing here needs a person to write it, and nothing a person needs requires them to read it.                                                                          | Two shapes for two directions. What an agent acts on is stated in full, reason beside rule, nothing left to be absorbed over time, with mechanical checks for what a sentence cannot hold on its own. What a person needs is reached without opening any of it — an interface over the record, and an orientation at the root. The limit: nothing stops an agent reading a rule and doing otherwise; what this removes is the excuse of not knowing.                                                                                                                 |
| **ARC-002** | The agent brings the intelligence; the repository brings everything else.   | The intelligence arrives general and knowing nothing about this place. What closes that gap is everything else — what it is told, what loads and when, what it may touch, what is checked afterwards. Keep that outside the repository, in a system prompt or an operator’s habit or a conversation that scrolled away, and the behaviour belongs to whoever set it up: it cannot be read, changed on purpose, or relied on next time. Models are also replaced, and this has to survive that without behaving differently. The failure is never refusal — intelligence short of its scaffolding improvises, competently, and the result reads as a decision. The test: swap the model, and the sessions should still be recognisable.                                                                          | One folder beside the record, `.claude/`, holding the whole of that scaffolding: the instructions loaded every session, the procedures that load when they match, the prompts a person invokes, the checks that hold what prose cannot, and the configuration binding them together. Versioned like everything else, so a change in how the agent behaves is a diff someone can read. The limit: what loads on a match can fail to match — so anything that must hold in _every_ session belongs in the always-loaded layer, never in something that might not load. |
| **ARC-003** | Everything personal lives in one place, nowhere else, and comes away whole. | Everything worth doing with the personal record — creating, editing, backing up, moving, locking down, deleting — depends on knowing exactly what is in it [[GDPR Art.30]](https://gdpr-text.com/read/article-30/ "A compliance regime for organisations processing other people's data. Corroborates why location must be knowable, not the choice to make a folder carry it."). Whether a piece of content is personal is a judgement made by whoever is looking, and a wrong one looks just like a right one. Where the file sits answers it without the judgement. Miss one file and the backup is short, the lock has a gap, the deletion is not complete, the move leaves something behind — and all four report success. Failure only shows from the outside: anything personal found there is a breach. | One folder at the repository root, `../data`: everything inside it is personal, wholly and exclusively, and no reading or judgement is required to know it. Segregation is enforced at the folder level.                                                                                                                                                                                                                                                                                                                                                               |
| **ARC-004** | The repository explains itself to a person, not only to the agent.          | The repository has two readers and serves one. The agent is handed an instruction file every session; a person is handed nothing, and arrives at the worst moment — inheriting it, or after the harness has stopped running. What they find instead is a file written to be obeyed rather than understood, which gives rules without saying what any of it is for. The record is meant to outlive the machinery that wrote it, so a person with no guide is the expected last reader, not an edge case. The test: open the repository knowing nothing, and see whether what it is, who it is for and where to start are answerable without asking.                                                                                                                                                              | One `README.md` at the repository root, written for someone who knows nothing and has nobody to ask: what this is, who it is for, what lives where, and what to read first. It points at the agent's instruction file rather than repeating it, so the two cannot drift. The limit: nothing checks that it is still true, and a stale orientation is worse than none — it is the one file here with no gate behind it.                                                                                                                                               |
| **ARC-005** | A person can read the record without reading the files.                     | The record is written in the shape that makes it retrievable — dated filenames, front matter, tags, one line pointing at another file. That shape serves the session that has to find things; it serves nobody who simply wants to read. And the person it belongs to is the one reader who never chose that shape: if seeing their own record means opening a folder of text files, they do not see it, and what cannot be seen cannot be corrected or trusted. A record held _about_ someone rather than _for_ them has changed hands without anyone deciding to. The test: a question about their own history, answered without a text editor.                                                                                                                                                               | One folder at the repository root, `../ux`, holding a read surface over the same files the sessions read — never a copy, so the two cannot disagree. It presents the record in the order a person reads rather than the order a session retrieves. The limit: it can only show what the files already say, so anything missing from the page is missing from the record, and a surface that starts filling that gap itself has become a second place the record lives.                                                                                                 |
| **ARC-006** | Superseded personal content leaves the live record, never the repository.   | The record is asked two things at once. Nothing written is lost — a gap cannot be noticed, and a record that must be re-checked is not a memory. And a session reads no more as the years pass — the budget is fixed, so a record that costs more each year is least usable when it holds most. Both hold only if what is no longer current has somewhere to go; without it the record is trimmed or read whole. A retired file that looks like a missing one is gone either way, so the move must be visible. The test: everything ever written still opens, and none of it sits on the default read path.                                                                                                                                                                                                     | One folder inside the record, `data/archive/`, for what has been superseded — excluded from the retrieval path and from nothing else. What moves there carries a dated note saying where it came from; what it left behind carries a pointer to where it went. It exists even when empty, so an empty archive is never mistaken for a record that has retired nothing. The limit: nothing tells a genuinely superseded file from an inconvenient one, and only the note makes that visible.                                                                          |
| **ARC-007** | The repository excludes only generated artifacts and environment-specific files. | A repository leaves things out for two reasons only: they are rebuilt from what it holds — dependencies, build output — or they belong to one machine — scratch, editor noise, credentials. Anything else left out is lost the day the machine is reclaimed, and nothing on disk says it was ever there; an exclusion is the one change that loses a file without a diff. The pull runs the other way too: a file that looks too sensitive to commit — the record itself — is exactly the one that must be kept. The test: every excluded path is rebuilt by a written step or is local to a machine, and nothing under the record matches any of them. | One ignore file at the root, each exclusion under a comment naming which of the two reasons it is, and the one inclusion that looks like a mistake — the record — stated there too, where a fix would be made. Credentials are matched broadly rather than by name, so a new one is caught before it is known. The limit: an ignore rule stops a file being added, not one already tracked, and nothing checks that a future unanchored pattern does not reach into the record. |
| **ARC-008** | Everything that configures the agent lives in one place, and moves as a unit. | Configuration — standing instructions, loadable procedures, invoked prompts, checks and settings — is built once and wanted again: in another repository, a fresh clone, a successor project. Spread across the tree, it cannot be lifted without finding every piece, and the missed piece shows up only as a session that behaves differently. What the agent works from is not configuration: the record comes away whole on its own (ARC-003), and the evidence base is reference that outlives any one agent. The test: copy that one place into an empty repository, and a session there loads the same instructions and procedures, with none of the record in it. | One folder, `.claude/`, holding the instruction file as `.claude/CLAUDE.md` beside the skills, commands, hooks and settings; Claude Code loads it from there as it would from the root. The specs (`specs/`) sit outside it at the root: they are the design the configuration is judged against, not configuration, and they outlive any one tool’s folder. The record (`../data`), the evidence base (`knowledge/`) and the read surface (`../ux`) sit beside them, so none moves with `.claude/` by accident. The limit: the folder’s name belongs to one tool, and nothing checks that new configuration lands inside it. |
| **ARC-009** | All scratch output goes to one disposable location. | Throwaway files left where the work happened get committed by accident, deleted alongside files that mattered, and blur what is working from what is lasting. One disposable place makes the line checkable: outside it is meant to last, inside it can go. The test: empty it, and nothing breaks or is lost. | One folder at the root, `temp/`, excluded from version control under ARC-007. Anything worth keeping moves to its proper home before the work ends. The limit: nothing empties or inspects it, and being untracked, it does not survive the machine. |
| **ARC-010** | Every folder has a single, documented responsibility. | A folder with no stated purpose collects whatever is convenient, and two with overlapping purposes split one kind of thing across both — then neither a reader nor the agent can guess where something lives. Writing the responsibility down makes a misplaced file visible and gives a new one an obvious home. The test: every folder on disk appears in the layout with its responsibility, and nothing in the layout is missing from disk. | The Repository Layout tree lists every folder with a one-line responsibility, and a folder that needs more carries its own README. A check compares the tree with the folders on disk and fails on a mismatch in either direction, as `check-links.mjs` does for citations. The limit: it confirms a folder is listed, not that its contents match the line. |
| **ARC-011** | Every file has a single, documented responsibility. | A file doing two jobs is found by neither: its name can describe only one, and whoever needs the other half opens it last or not at all. An agent reads a file’s name and opening lines before deciding to load the rest, so a file that does not say what it holds is either loaded for nothing or skipped when it was needed. One job, stated at the top, lets a file be found, loaded and changed without touching anything else. The test: read only a file’s first lines, and say correctly what it holds. | Each file opens by stating its job — a heading and one-line lede for prose, frontmatter where a tool reads it, a header comment in code. A file that grows a second job is split, and whatever indexes it is updated in the same change. The limit: JSON takes no comments, so a JSON file states its job in a named key, as `settings.json` does in `_note`; and nothing checks that the opening still matches the contents. |
| **ARC-012** | File names follow one convention per kind of file. | A listing is read before any file is opened. When each kind of file is named one way, the listing is already an index: dated entries sort by time, a person’s file is found by their name, and the file that governs a folder stands out from those it governs. Mixed names within one kind turn every lookup into opening files. The test: from a folder listing alone, every file’s kind can be told correctly. | Governing and index files in uppercase, `README.md`, `INDEX.md`; dated entries as `YYYY-MM-DD.md`, the one date form that sorts as text; people as `firstname.md`; other record files in snake_case; other harness files in kebab-case; code in its language’s own convention. The scheme is written down once, beside the layout, so a new file is named by rule and not by precedent. The limit: the record and the harness differ by history, not by reason, and nothing checks any of it. |
| **ARC-013** | Every fact has one authoritative home; everything else points to it. | Duplication does not look like duplication; it looks like two records that disagree, with nothing to say which was written later — and the copy is the one that stops being updated. A spec restating another’s rule, or a skill restating a spec, is the same failure inside the harness. The test: pick any fact, and exactly one file states it; every other mention links to that file. | Each ledger owns one kind of thing — the timeline dated events, the index standing files, the session log sessions, each spec family its own questions — and says so at its top (ARC-011). Cross-references link and never copy the text. The limit: nothing detects a copy; a restated rule reads as agreement until the day it doesn’t. |
| **ARC-014** | A move never leaves a broken link. | Rearranging is expected — folders split and files are renamed as the repository grows — and a move is safe only if it is only a move. A link that points at nothing is indistinguishable from a deletion to the session that follows it [[FAIR F1]](https://book.the-turing-way.org/reproducible-research/rdm/rdm-fair/ "Written for published research data in a registry shared between institutions. The principles transfer as an account of what findability costs; their machinery - resolvable identifiers, schema-validated metadata, an external registry - does not, and here each is upheld by discipline instead."): the thing still exists but can no longer be found. The test: after any move, every path and spec ID cited anywhere resolves. | A move updates every pointer to it in the same commit, and `ux/scripts/check-links.mjs` fails on any path or spec ID that resolves to nothing. For the record, DAT-001 adds that a move must serve retrieval. The limit: the check reads paths and IDs, not headings or prose, so *"see the section above"* can still dangle. |
