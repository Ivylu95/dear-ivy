# Skills [SKL]

The binding specification for the harness's procedures: what must hold of the skills that load themselves and the commands a person invokes.

> 🔒 **An agent may not edit this file.** The prohibition extends to any alteration of it, rewording, reformatting, renaming and moving included, and admits no exception for a change the agent judges harmless. Where an agent finds anything wrong, inconsistent or improvable, it records the finding in [`REVIEW.md`](../REVIEW.md) with its reasoning and leaves the entry for a person to clear, never treating its own entry as settled. Until a person applies a change, this file is complied with as written; where it and the repository diverge, the repository is wrong.

---

## Purpose and Scope

The provisions below fix this specification's purpose and the reach of its authority — how this file is to be read, obeyed, and bounded. The register further down governs the harness's procedures instead.

| #   | Provision | What it means |
| --- | --- | --- |
| 1   | **This specification is the single source of truth for the harness's procedures.** | A folder of procedures shows only which ones exist, and commit history only when each changed; neither states what a procedure must be true of. This file states it, and an agent treats it as the source of truth whenever it writes, changes or starts one. The reading rules, the binding rule and the approval gate in [`README.md`](../README.md) apply to this file unchanged. |
| 2   | **It governs how a procedure is kept and started, never where it lives.** | *Where* skills and commands are kept is architectural, and stays in [`ARCHITECTURE.md`](ARCHITECTURE.md), whose Repository Layout draws both folders. *What must hold of a procedure once it is there* lives here. SKL-001 was the seventh row of the architecture register until 2026-09-21, and moved here unchanged. |
| 3   | **This specification binds where it speaks and defers where it is silent.** | Compliance is mandatory: an agent chooses how to satisfy a row, never whether to. Silence confers no authority to invent a requirement and attribute it here; where something ought to hold and nothing here provides for it, the omission is a gap and is raised. |

## Specifications Register

The normative part of this file. Each row is one thing that must be true of the harness's procedures; how a row is read is in [`README.md`](../README.md).

> ⚠️ **When referencing:** always cite a row by **both** its ID and its spec statement — IDs shift, specs get removed, and ordering isn't guaranteed.

| ID | SPEC STATEMENT | SPEC RATIONALE | DESIGN RECOMMENDATION |
| --- | --- | --- | --- |
| **SKL-001** | A prompt worth running twice is kept where a person can invoke it. | A prompt that works is the result of several that did not, and what makes it work is the wording. Memory does not hold wording: retyped, it comes back shorter and vaguer and different each time, so two runs of the same procedure stop being comparable and nobody can tell that this month's was worse. Keeping it makes the prompt something that can be read, changed on purpose, and run again word for word. And it is a prompt _for_ the agent, so the agent is not what starts it — a procedure that drives the machinery should not be chosen by the machinery. The test: the prompt behind a good result last time can be run again unchanged. | A folder of its own, `.claude/commands/`, one file per prompt, invoked by name. The file _is_ the prompt, so a change to how the procedure runs is a diff like any other rather than undocumented drift in someone's head. It carries no _when to use this_ description — that is a skill's shape, and it is what would let the prompt start itself. The limit: nothing stops the same prompt being pasted into a conversation instead, which works once and leaves nothing behind. |
| **SKL-002** | A repeated procedure becomes its own loadable unit, not more text in the always-loaded layer. | Every line in the always-loaded layer is paid for in every session, whether the session needs it or not, and a procedure written there crowds out the rules that must hold everywhere. Loaded on match, it costs nothing until it is needed. The exception is anything safety-critical: a unit that fails to match is a unit that did not run, so safety stays always loaded (SAF-001). The test: the always-loaded layer holds no procedure that only some sessions use. | The third time a multi-step workflow is done by hand, it becomes a skill — its own file, with a description written as when to use it, and a row in the router. The limit: loading on a match can miss, and nothing measures how often a skill that should have loaded did not. |
| **SKL-003** | Adding a route never silently removes a rule.                                                     | The fallback is doing the work, not the router. Write it for the case where the route is never reached, or it will end up written for the case where it is. This is what makes SAF-001 survive a bad match.                          | Each route declares, in the same place, the rule that must hold even if it never fires. Adding a route and adding its fallback are one change, not two.                                                                       |
| **SKL-004** | A procedure the agent follows is written from current practice, not from memory. | Guidance on writing procedures for an agent moves faster than any model's training, and a procedure written from memory reads exactly as confident as one written from evidence. Compliance is judged by every procedure recording what it was grounded on, and when. | A skill-writing skill that, before a skill is drafted, searches current guidance on writing skills and on the task itself, and records the sources and date in the skill's own log. Falls short in that search returns what is popular rather than what is right, and a log proves a search happened, not that it was read well. |
| **SKL-005** | A procedure the agent follows is re-checked against current practice on a fixed interval. | A procedure grounded once goes stale without anything breaking: it keeps running, and reads as current as the day it was written. Compliance is judged by every procedure's record carrying a last-checked date inside its interval. | Each skill's log carries its last check, its next due date and one prediction for the next check to grade. Once the date has passed, the task in hand finishes first; the re-check follows in a developer's session, and in one of hers only a finding is written. The check is recorded even when nothing changed. Falls short in that the check fires only when the skill runs, so a skill nobody uses goes stale unseen, and an overdue skill runs as written until a developer takes it up. |
| **SKL-006** | A change the person asks for in how it works takes effect without anyone else's involvement. | The person only ever has to talk, and a request queued for a developer the person never sees is a request that quietly died. The core stays out of reach all the same: MNT-006 binds a change asked for as firmly as one the agent chose. Compliance is judged by asking, in one session, for a new way of working, and finding the next session doing it with nothing done by anyone else. | A request about tone goes to the person's own file of how to be spoken to; a request for something new becomes a local skill, written by the skill-writing procedure, with its row in the router, committed and pushed in the same turn. Falls short in two places: whether a request touches the core is the agent's judgement, checked by nothing yet; and the developer never sees a local skill, so a later update may duplicate or contradict it. |

> 📚 **No row above carries a source tag, and that is a value rather than an omission.** These registers govern one person's private record; where no published work genuinely addresses a row it stays bare, and reaching for a large name to decorate one is the failure mode — see **Source tags** in [`README.md`](../README.md). The works cited elsewhere in these specs, and the boundary past which each stops applying, are in [`REFERENCES.md`](../REFERENCES.md).
