# Sample Record [SMP]

The binding specification for the second, fabricated record: what must hold whenever the system reads one record in place of another.

> 🔒 **An agent may not edit this file.** The prohibition extends to any alteration of it, rewording, reformatting, renaming and moving included, and admits no exception for a change the agent judges harmless. Where an agent finds anything wrong, inconsistent or improvable, it records the finding in [`REVIEW.md`](../REVIEW.md) with its reasoning and leaves the entry for a person to clear, never treating its own entry as settled. Until a person applies a change, this file is complied with as written; where it and the repository diverge, the repository is wrong.

---

## Purpose and Scope

The provisions below fix this specification's purpose and the reach of its authority — how this file is to be read, obeyed, and bounded. The register further down governs the fabricated record instead.

| #   | Provision                                                                | What it means                                                                                                                                                                                                                                                                                                                                 |
| --- | ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------- |
| 1   | **This specification is the single source of truth for substitution.**   | A tree on disk shows only that a second record exists, and commit history only when it was added; neither states what it is for or what it may never do. This file states both, and an agent treats it as the source of truth whenever anything reads a record. The reading rules, the binding rule and the approval gate in [`README.md`](../README.md) apply to this file unchanged. |
| 2   | **It governs existence and conduct, never location.**                    | *Where* a fabricated record is allowed to live is architectural — it is a root-level tree beside the real one, and **ARC-003** owns that. *That it may exist at all, and what it may never do*, lives here. The procedure that fills and refreshes it is a skill, not a row. |
| 3   | **One row here is a safety property, and it outranks the rest of the file.** | SMP-001 — that content the system did not receive from her is never presented as though it had been — is not a matter of build hygiene. Where any other row here would be satisfied by weakening it, SMP-001 governs, and [`../interaction/safety.md`](../interaction/safety.md) outranks all of them. |
| 4   | **This specification binds where it speaks and defers where it is silent.** | Compliance is mandatory: an agent chooses how to satisfy a row, never whether to. Silence confers no authority to invent a requirement and attribute it here — see **Not specified here** below for what is deliberately left to design. |

## Specifications Register

The normative part of this file. Each row is one thing that must be true of the fabricated record; how a row is read is in [`README.md`](../README.md).

> ⚠️ **When referencing:** always cite a row by **both** its ID and its spec statement — IDs shift, specs get removed, and ordering isn't guaranteed.

| ID | SPEC STATEMENT | SPEC RATIONALE | DESIGN RECOMMENDATION |
| --- | --- | --- | --- |
| **SMP-001** | Content the system did not receive from her is never presented as though it had been. | This is the only row here that is a safety property, and it outranks the rest of the file. The failure is silent rather than loud: a surface rendering invented days under her name, formatted exactly as her own, with nothing to say otherwise. Anything that can be switched off elsewhere — an environment variable, a build flag, a per-route condition — will eventually be switched off by someone who did not know what it was for. A marker carried by the content travels with it into every copy, and the one thing that breaks the mark is deleting the thing it describes. Judged by deleting the marker and confirming the fabricated content stops being readable as hers, not merely that a banner disappears. | Mark the fabrication inside the fabricated content itself, and render the mark from that marker on every page — not dismissible, not a notification, not conditional on a route. |
| **SMP-002** | A fabricated record exists for one purpose: so the surface can be examined without opening hers. | The cheaper thing is a fixture module, and it proves nothing. A preview rendered down its own code path demonstrates that the preview works; it says nothing about the parsers, the sort orders, the empty states or the layout that the real record will meet. It also decays differently: a fixture drifts from the record's shape without anything looking wrong, whereas a record-shaped tree fails the same checks the real one does. The cost is that it must be maintained like a record — see SMP-007. | Build it as a whole record of the same shape as the real one, not as fixtures, factories or seeded objects. |
| **SMP-003** | Which record is being read is decided in exactly one place, and the reading itself does not know the answer. | Two places that answer "which record" is the shape of the bug where a surface reads one folder and writes into another, or where one panel on a page is fabricated and the rest is hers. Threading the answer through every read is the same hazard wearing a parameter: the one call site that forgets is not a crash, it is a page that renders perfectly and is wrong. Judged by whether a new view can be written without knowing this spec exists. | Resolve the choice once at the boundary of a request and carry it down to the reads; keep the parsing layer ignorant of it, with no branch anywhere for "sample mode". |
| **SMP-004** | Nothing in a fabricated record is ever taken from a real one — not a name, not a sentence, not a date. | "Based loosely on" is the leak that looks like a sample: it survives review precisely because it reads as invented, and it is the form in which real material travels furthest, since a fabricated record is the part of the repository nobody thinks to treat as personal. The check has one predictable failure mode — the temptation on a red build is to exclude the file rather than rename the person — so the rule has to be written down where the exclusion would be added. An exclusion here is a permanent hole in the only mechanical control over this row. | Check it mechanically against the real record and fail the build on a collision. When it fires, rewrite the invention. |
| **SMP-005** | A viewer's choice of what to read never changes where a write lands. | Two failures, opposite and both bad: her content written into a fabricated record — which is non-personal, git-tracked harness, and reviewed as such — or fabricated content written where hers goes. The switch is a viewing preference and nothing more; letting it steer a write makes "what am I looking at" and "whose is this" the same question, and they are not. Presentation follows the same line: while a fabrication is on screen, her own material shown beside it reads as a claim about who this is. | Bind the write path to the real record where it is defined, so the choice cannot reach it, and suppress in the viewing surface anything personal that the fabricated record has no counterpart for. |
| **SMP-006** | The absence of a fabricated record is not a failure state, and an unrecognised choice resolves to the real one. | A clone, a deployment or a checkout without the fabricated tree is a normal condition, not a broken install, and it must not present a control that does nothing or a view that looks like data loss. Falling back to her record rather than to an empty one is the safe direction for the same reason: an empty shell is indistinguishable from a record that has been lost, and that is a sentence nobody should read by accident. | Offer no switch where there is nothing to switch to, and treat an unknown or stale request as a request for her record. |
| **SMP-007** | A fabricated record is kept current with the real one — in shape, and in time. | It goes stale in three ways and every one of them is invisible: dates that were in the future fall into the past and the views that read forward empty out; a new surface arrives with nothing to show in it; the real record grows a file or a heading and the fabrication no longer proves anything about the code that reads both. None of these fails a check, none looks like a bug, and the result is a fabricated record that has quietly stopped standing in for anything — which means the surface is once again only testable by opening hers. | Give the work a written procedure rather than leaving it to whoever notices, and treat a stale fabrication as a defect against this row rather than as cosmetic. |

> 📚 **No row above carries a source tag, and that is a value rather than an omission.** These registers govern one person's private record; where no published work genuinely addresses a row it stays bare, and reaching for a large name to decorate one is the failure mode — see **Source tags** in [`README.md`](../README.md). The works cited elsewhere in these specs, and the boundary past which each stops applying, are in [`REFERENCES.md`](../REFERENCES.md).

## Not specified here

**How the choice is offered.** That it must be a deliberate choice, and that it cannot reach a write, is SMP-005 and SMP-006; whether it is a control, a flag or a separate address is design.

**What the fabrication contains.** Coverage — that no view renders its empty state — is a consequence of SMP-002 and SMP-007, not a row of its own. The shape it must fill belongs with the procedure that fills it.
