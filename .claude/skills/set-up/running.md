# Running a step

**Read when** in any development chat, every run, a *NEW COPY* too.

**A run's last line, even paused or waiting on an answer: *This run taught: …*.**

**Every run records what it hit, that turn** (A-016). That means a block, a failure, a wrong turn, a step unlike its service's page, or a gap (a question back, "it doesn't work", "it looks different"). Before the next step, each gets its dated case in `dev/skills/set-up/cases.md`, the step fixed (`dev/skills/set-up/README.md`), and a line opening *Gap noted:*. A question is answered from the page fetched now.

**Before handing over a click path, a limit or a command in another service, fetch its current page** from its own domain, never the step's text or memory. Where they differ, follow the page and fix the step in the same run, address and date beside it.

**A commit the gate refuses** (`pre-commit: commit refused`): nothing is lost and nothing pushed, earlier commits standing. Stop and hand it to the developer: never `--no-verify`, never an edit, rename or move in the copy to pass it.

What it cannot see (a click, a phone, a secret) rests on a word or a log, and either may be optimistic. **Ask which copy first** when unsure (*"my own copy"* in the developer's checkout is this one). In **check** mode, ask before a fix; a broken part outside the request that holds her saves is named and its repair asked about, never done silently. During a repair, read the record's **shape** only (names, counts, dates, commit subjects). A setup lays the pipe; it never speaks for her. A run that changes a file commits what and why, its body naming `set-up@` and `git log -1 --format=%h -- .claude/skills/set-up`; one that changes nothing leaves nothing (`PMM-014`).

## The development reply

The development reply shape wraps the run (a *NEW COPY* outside development mode keeps its marks, without a header). The breadcrumb carries the steps (the new copy's or the part's). The body has one line per step, `✅ done · 🔵 now · ⬜ to do · ❔ can't be seen from here · ❌ broken · ➖ does not apply`, each with its evidence or *your word*. Past halfway, finished lines collapse to a count. One step per message, then stop. **But a step their answer closes (declined, done here) ends, and the next begins, in that reply.** A message holds the step and **what they should see** on its own line. Where something went wrong, one plain sentence first says what is and is not lost.

**Walked or the sheet.** Walk it when Claude Code runs on the computer being set up and sees its results. Otherwise offer the sheet (`new-copy-run.md`) unasked. Nothing is marked from a sheet; one part closes by asking what its *You should see* line showed.

## Who does each step

**Read the environment** (cloud or local, platform, whose copy, which tools) to know who does each step. A step this session can do (an edit, a commit, reading a log) is done, not described. One inside someone else's interface gets the exact click path, and which doctor line turns ✅ when it took. Where theirs differs or a name is not found, ask for a screenshot. **Always the person's**: every secret (into the service's own web form), a scheduled task's repository and environment, the Actions write permission, the GitHub App, the phone, any branch deletion. On a work computer, even for his own copy, every token and sign-in goes in a private window, closed afterwards.

## Grounding

**A page unreachable from here**: name the host for its owner to allow in network settings. Meanwhile a web search's summary or the person's screenshot stands in. A step changed on those alone stays `unsourced` in its case until a page confirms it. **A lesson becomes a rule only on a source fetched in the run** (an official page, a log line, the doctor), dated in the case; one on recall stays `open (unsourced)`. At the start, `node .claude/hooks/lib/currency.mjs`; when `dev/skills/set-up/log.md` says due, a fresh subagent runs its search in the background, weighed at the end by someone other than the rule's author (`PRC-006`).
