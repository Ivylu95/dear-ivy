# Step 15: the check-in nudge and reminders on Telegram (only if wanted)

**Read when** a new copy reaches step 15 ([`new-copy-close.md`](new-copy-close.md)), or a Telegram part (`components.md`) is added or renewed; 15.5, the routine, is [`telegram-routine.md`](telegram-routine.md)'s. Items 15.1 to 15.4 are here, with the parts `heartbeat-workflows`, `secrets` and `pipe`, while `routine` and `reminders` are 15.5's. Every account in these steps is theirs, signed in as them (`new-copy.md`'s opening).

**A question back on a click path** (*"I don't see it"*, *"it looks different"*): **never repeat the path, nor give one from memory.** That same turn, fetch the service's page now (for 15.3, GitHub's docs on Actions secrets) and answer from it, saying so. If the page is unreachable, ask for a screenshot of what they see. Then write its dated case, fix the step with the page's address and date, and add one line *Gap noted:*. Give the next step only once it is answered.

**Every click path here is checked against the service's page fetched now before it is handed over** (`running.md`). Where it differs, follow the page and fix the step the same way.

**Declined** (*"she doesn't want Telegram"*): disable `heartbeats.yml` (`remove-move-retire.md`), which otherwise starts every two hours, set up no secret, and begin step 16 in that same reply.

Only if they want messages between conversations. This lays the pipe; they turn the check-in nudge on themselves, in a conversation (`CON-009`). First tell them its one real cost: Telegram holds each message readable, and it can show on a locked screen. No Cloudflare account is needed (A-054). Each token's end goes in data/core/state/setup_notes.md as `- expires · <date> · <which token>`, so the doctor warns before it stops anything. The doctor warns only when run, so a helper also puts a reminder in their own calendar a month before each.

**Words used here:** a *bot* is a Telegram account a program sends from. A *token* is a long password a service makes for one purpose, kept like a password and never typed into a chat. The *chat ID* is the number Telegram gives the conversation between them and their bot. A *secret* is a value GitHub keeps hidden and hands only to the repository's workflows.

1. **Their bot.** **Where:** their phone, in Telegram, signed in as them. Telegram → **@BotFather** → `/newbot`, answering its prompts until it replies with the token; copy the token. They message the bot, then open `https://api.telegram.org/bot<token>/getUpdates` in a private window on their own phone: the number after `"chat":{"id":` is the chat ID. **You should see** BotFather's reply holding the token, and the page showing `"chat":{"id":` followed by a number. **If not:** if the page reads `"result":[]`, send the bot a message, then reload. If it reads `"ok":false`, the token was copied wrongly, so copy it again.
2. **The workflows.** `check-in.yml` (by hand) and `heartbeats.yml` (the routine's backup, every two hours, about 360 of GitHub's 2,000 free minutes a month) came with the download. A cloud push of workflow files may be refused, so push them from a computer. **You should see** `check-in` and `heartbeats` listed in their repository's **Actions** tab. **If not:** push missing files from their computer. Turn one listed as disabled on from the same ⋯ menu that disables it (`remove-move-retire.md`).
3. **Three secrets** go in their repository's Settings → Secrets and variables → Actions, signed in as them, in a browser. They are `CLAUDE_CODE_OAUTH_TOKEN` (from `claude setup-token` on their machine as them, in its terminal, lasting about a year), `TELEGRAM_BOT_TOKEN` and `TELEGRAM_CHAT_ID`. Enter them in the web form, since a hidden terminal prompt has saved one empty. **You should see** the three names listed as repository secrets; their values are never shown again, by design. **If not:** add a missing or misspelled name again, exactly as above. Enter a value that may be wrong again under the same name, which replaces it. **Renewing one** (*"a token is expiring"*): add the new one the same way, its end in the setup notes. Then remove the old one too. Never assume a new `claude setup-token` ended it, since the docs do not say. Its owner removes it in claude.ai Settings → Account (Claude Code sign-ins, `setup-token` ones included). If it is not listed there, it is under Settings → Claude Code, the trash icon ([help article](https://support.claude.com/en/articles/10310342-how-do-i-log-out-of-all-active-sessions), read 2026-11-01).
4. **Prove the pipe.** Run it only with the phone owner's yes that day, relayed by the developer when the phone is someone else's. Never run it while the doctor reads `paused`, unless that owner says to (`repair-messages.md`). Go to Actions → `check-in` → Run workflow → *test_nudge*, which sends one test line from a throwaway record. **You should see** the run go green ending `nudge: sent from GitHub`, and the line on their phone. **If not:** a red run, or green with nothing on the phone: [`repair-messages.md`](repair-messages.md)'s rows, from the run's named lines only.

Then [`telegram-routine.md`](telegram-routine.md), step 15.5.
