# Repair: privacy, accounts and secrets

**Read when** a secret is out of place, a sign-in or login is in question, a GitHub email arrives, or the doctor reads `remote` or `copy-for` broken (`SKILL.md` § 3). Start from the doctor and finish on it, as `repair.md` does. In her own chat, each row's answer is `her-side.md`'s: one plain line and a setup note, never steps.

| What is seen | Part | What separates it, and the fix |
|---|---|---|
| The doctor's `copy-for` reads broken: `dev/` in a copy made for someone else | `copy-for` | Broken, said so: her chats would run with development rights. Propose removing `dev/` in one commit, then finding how it came back (`new-copy-download.md` steps 3 to 5). Its `claude-md` broken (her `CLAUDE.md` changed other than by an update): a person reads each diff; one not from a release goes back with `git revert`, the developer told |
| The doctor's `remote` broken: the repository public, or a collaborator besides her | Privacy | A person acts now, signed in as her, in a browser, in the repository's own Settings (its click path from GitHub's page fetched now, `running.md`): the repository made private again, every other collaborator (another account given access) removed; then the doctor. **You should see** its `remote` ✅. **If not:** the doctor names which of the two is still open |
| A token, key or chat ID seen where it should not be (a chat, a log, a remote URL, shell history) | `secrets` | **Never repeated or quoted, never used again.** Its owner, signed in as themselves, revokes it at its source (a bot token with @BotFather `/revoke`; others, their part's *Removed by* in `remove-move-retire.md`), enters the new one as a secret in the web form, its expiry date in the setup notes, then the doctor (**you should see** its `secrets` and `expiry` no longer broken). The Claude token is removed as its *Removed by* says; the docs do not say whether a new one ends the old, so the old one is removed too. A chat ID cannot be revoked; with the bot token replaced it reaches nothing. A password or recovery code is hers alone: changed now in that service's own settings, by her |
| *"I can't sign in"*; someone asks for her login | Her account | Her recovery codes (`new-copy.md` step 1) let her back in; without them, only GitHub support can, and may not: said plainly. A code is never typed into the chat. Her Claude account signs in by email. Her login is hers alone, never given: a helper's fix is done with her signed in herself |
| A lost or stolen device | Her account | Her record is on GitHub, not the device: she changes her GitHub password, then signs out its other sessions (both in GitHub's own settings, their path fetched now); a setup note. **You should see** her GitHub sessions list only devices she still holds |
| An email from GitHub: a token expiring, a sign-in alert, a run failed | `expiry`, `remote`, `heartbeats` | The doctor first, then that part's row. A sign-in she does not recognise is her account: she changes the password and checks two-factor herself. *A run failed* every two hours is `heartbeats.yml` after its token expired: whoever set it up renews it (the `secrets` row above), or disables `heartbeats.yml` if nobody will |
