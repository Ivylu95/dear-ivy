# data/

Everything in here is hers. Her words, her history, her record. Nothing outside
this folder holds anything personal.

This file is the map: which folder, and what belongs in it. `INDEX.md` beside it
is the next layer down — which file, one line each. Two tiers on purpose, so a
session reads a short orienting layer every time and drops into the detail only
for the part it needs.

## The map

| | |
|---|---|
| `timeline.md` | **The spine.** Every dated event, in order — Eras first, then entries. Read after `state/now.md`. |
| `INDEX.md` | The standing, undated files, one line each. |
| `profile.yaml` | Who this is for, and the essentials needed before any conversation. Everything else here is prose. |
| `state/` | Working memory — the current snapshot, the session log, open threads. |
| `me/` | Who she is, what she wants, what helps, how to speak to her, patterns she has named. |
| `people/` | One file per person, named for the name she uses. |
| `journal/` | Dated entries. |
| `therapy/` | Appointments, and the current clinical focus. |
| `calendar/` | What is coming, and the dates that land hard every year. |
| `safety/` | Warning signs, what helps, who to call. |
| `assets/` | Files that are not words. See the note in the folder. |
| `archive/` | Superseded material. Nothing is deleted — it moves here. |

## The rules are not here

Why this folder is committed rather than ignored, why privacy comes from the
repository being private rather than from holding files out of it, and what a
commit message may name — those are specification, and they live in
[`specs/`](../specs/). Stating them here as well would be a
second copy that disagrees with the first the day one of them changes.

What stays in this file is the map, because a map belongs next to the territory.
