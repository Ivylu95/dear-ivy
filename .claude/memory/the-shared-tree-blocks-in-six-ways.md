# The shared tree blocks in six ways

Many sessions share one working tree, one index and one `.git` on this machine
(the developer's chats, heartbeat runs, her conversations, and a chat's own
background agents). From 2026-10-09 each of these stopped work, and none is
visible from the code.

| What happens | What it looks like | What to do |
|---|---|---|
| **Another chat's uncommitted files block every pull.** A heartbeat's unwritten backlog lines, or a chat's half-done change, leave files a pull would overwrite. | `git pull` aborts "Please commit your changes or stash them"; her saves commit locally but never push (six sat local, 19:48 to 21:20, 2026-10-10). | Never stash or commit another session's files to clear it. Push your own commit by merging it onto the remote main in a scratch worktree (`git worktree add --detach <scratchpad>/wt origin/main`, merge, `git push origin HEAD:main`, `git worktree remove`). Unpushed saves go the same way. A heartbeat's leftover backlog lines, in format and from a finished run, may be committed as its own. |
| **Two commits at once swap messages.** Git writes the message to the shared `.git/COMMIT_EDITMSG`, runs the hook, and reads the file back. | A commit carries another chat's message over your content (1210a07, 2026-10-10). | It cannot be amended (history is never rewritten). Say so in the reply; the content is what counts. Retrying a refused commit in a loop raises the odds. |
| **A dead process leaves `.git/index.lock`.** | Every commit fails "Unable to create index.lock: File exists"; no git process is running. | The history guard refuses any agent deleting inside `.git`. Check no git runs, then give the developer: `if (-not (Get-Process git -ErrorAction SilentlyContinue)) { Remove-Item <repo>\.git\index.lock }`. |
| **Parallel builder worktrees fill the disk.** Each agent worktree with its own `npm ci` and two builds is about 650 MB; heartbeat checkouts in `temp/` are about 520 MB each and are left behind. | ENOSPC in the commit gate; C: fell to 76 MB with four builders running (2026-10-11), when her saves could fail too. | Check free space before spawning builders (`(Get-PSDrive C).Free`); four need about 3 GB. Deleting folders is the developer's: hand them `git worktree remove --force` for finished checkouts, never the live `temp/hb-run`. |
| **A test passes on Linux and fails here.** `node --import <absolute path>` is refused on Windows (ERR_UNSUPPORTED_ESM_URL_SCHEME). | CI green, every local commit refused by the gate's unit tests (ux/test/auth.test.mjs, 2026-10-10). | Pass a `file://` URL: `new URL('./x.mjs', import.meta.url).href`. |
| **Your own background agent's half-done work reads as yours.** A subagent started with `run_in_background` edits the same tree while you reply. | The Stop check reports uncommitted harness changes, or a review owed, for files you never touched (chat of 2026-10-12 to 10-15). | Wait for its hand-back, then let it commit, or commit its finished work as its own. Never commit its half-done files to quiet the check, and never revert them. |

| **One agent's unstage is everyone's.** The index is shared, so `git restore --staged .` from one agent unstages files another agent staged for its own commit. | A parallel agent's commit lands without files it had staged (2026-10-16, reported by the agent that ran it). | Brief every parallel agent to stage named paths only and commit with `git commit -o <paths>` or `git add <paths>`; never `git restore --staged .` or `git add -A`. |
| **The release test and the hook self-test share `temp/`.** One clears it while the other runs from it. | Either fails at random with a missing sandbox (hit twice, 2026-10-16). | Run them one after the other, never together, and never while a background agent may run one. |
| **Two of a chat's own agents in one tree commit and merge over each other.** | One gets "index.lock: File exists" while the other's commit is still running (a live lock, not a dead one); a pull is blocked by the other's half-written files; failed merges leave `.merge_file_*` copies in the root, untracked (six on 2026-11-03); the Stop check asks to commit the other's files. | Wait for the running commit and retry; never delete a lock while a git process runs. The `.merge_file_*` files are git's scratch copies for a merge driver: once `git status` shows no merge in progress, they can go. Better, never share: five agents briefed with worktree isolation on 2026-11-03 to 04 ran with no collision. Since 2026-11-04 it is the rule (`DEV-017` design 6, `dev/AGENTS.md`): every agent that edits or commits gets its own worktree, and in Claude Code a subagent's commit in a checkout another writer is working in is refused (`.claude/hooks/session/guard-agent-own-copy.mjs`). Its brief says "fetch and merge origin/main first; stage named paths only; commit with `-F` from a message file with your own prefix; push `HEAD:main`, retrying on rejection", and the coordinator reads each hand-back's commit before relying on it. The gate links the ux node_modules itself now (`linkPackages` in `.claude/hooks/lib/worktree-packages.mjs`). |
