# Search the agreements by what a proposal does, not its name

**Seen 2026-10-29.** Before recommending a weekly "re-grounding" heartbeat, `dialogue.mjs ask`
was run on `re-ground`, `spec review`, `backup restore` and `branch cleanup`. Nothing bound. But
A-015 says, word for word, "No heartbeats for keeping a skill up to date": the proposal's name
never appeared in it, its effect did. The owner said yes to a job that broke their own agreement,
and it was caught only when the jobs README cited A-015 while building.

**Do.** Ask on the words for what the proposal would do and to what (`heartbeat skill`, `keep up
to date`), as well as its name, and read the cards the listing marks as sharing words. A clash
found after a yes is put back to the owner before anything is built.

**Also seen.** A hook that already carried A-015 matched only the Skill tool, while development
skills are loaded by reading their page, so their check never ran: when an agreement says
something happens "when X is used", check every way X is used.
